# Link-preview crawlers

What a share card has to satisfy, and which parts are checked by this package. "Documented" means the
platform's own guidance says it; "observed" means we saw it on a production site; "unverified" means we have
not tested it.

| Requirement                                                     | Status                                                                                        | Where it is handled                                                                                                                                         |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An absolute `https` image URL in `og:image` and `twitter:image` | documented (Facebook, LinkedIn, X)                                                            | `ogMetadata` builds it from the Payload `serverURL`; the kit's `everyRouteHasOwnCard` checks it                                                             |
| 1200x630 (1.91:1), at most a few hundred KB                     | documented; the size budget is observed                                                       | templates default to 1200x630; the kit's `sizeBudget`                                                                                                       |
| `og:image:width`, `height`, `type` and `alt` present            | documented (LinkedIn reads the size; without it the first share can show no image)            | `ogMetadata`; an upload with no size on record is never advertised                                                                                          |
| No redirect between the advertised URL and the bytes            | documented                                                                                    | the card route answers 200 at the advertised URL                                                                                                            |
| HEAD answered like GET                                          | observed: LinkedInBot HEADs first and drops an image whose HEAD is 404                        | `HEAD = GET` on the card route, `withHead` on Payload REST; the kit's `headParity`, `restHeadParity`                                                        |
| `Allow` for the card path in `robots.txt`                       | documented                                                                                    | yours: do not `Disallow` `/og/` (a sample is in [reference](reference.md#crawlers))                                                                         |
| A new URL when the image changes                                | documented (platforms cache by full URL)                                                      | the `?v=` version; a stale `?v` still serves the current bytes for an hour, so a platform that cached them under the old URL keeps them until it re-scrapes |
| The page advertises the current URL                             | yours: a page Next caches keeps the `?v` it was rendered with                                 | [reference](reference.md#pages-that-next-caches): revalidate on save, or render on every request                                                            |
| A new card URL is shown only after the page is scraped again    | documented (LinkedIn Post Inspector, Facebook Sharing Debugger)                               | the admin's "Force new image" gives the card a new URL; re-scrape the page in those tools                                                                   |
| X accepts JPEG, PNG, WebP, GIF in a large card, never SVG       | documented                                                                                    | eligibility rules                                                                                                                                           |
| Which image formats `og:image` may be                           | see [Image formats](#image-formats): JPEG and PNG everywhere we could check; WebP is not safe | `format: 'jpeg'` for photo cards; `format: 'webp'` is opt-in                                                                                                |
| A fast first fetch (a crawler gives up on a slow one)           | observed                                                                                      | the render queue and the store; `crawlerEvents` shows the share of cold renders                                                                             |
| Telegram and WhatsApp refetch behaviour                         | unverified                                                                                    | a change of the URL is the only dependable way to refresh a card there                                                                                      |
| Facebook scrapes both HEAD and GET and caches for about 30 days | observed                                                                                      | re-scrape with the Sharing Debugger after a change                                                                                                          |

## Image formats

Why the plugin's photo-card format is JPEG, and WebP is opt-in (`format` in [reference](reference.md#jpeg-and-webp-cards)). Checked 2026-11-25
against each platform's own pages where they exist; "unverified" means the platform says nothing and we have not tested it on the platform itself.

| Platform                  | PNG, JPEG                                                                                                                                                                                                                                       | WebP                                                                                                                                                                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Facebook / Meta           | unverified: [Meta's image page](https://developers.facebook.com/docs/sharing/webmasters/images/) gives size limits (8 MB) and no format list; JPEG and PNG are what every guide assumes                                                         | unverified: the same page names no formats; third-party guides disagree                                                                                                                                                                |
| LinkedIn                  | documented: the [help page](https://www.linkedin.com/help/linkedin/answer/a521928) shows a `.jpg` `og:image` and its image spec lists JPG, PNG, GIF                                                                                             | unverified, reported unsupported: the same help page does not list WebP, and several third-party checkers report a WebP preview is dropped                                                                                             |
| X                         | documented earlier in this file (JPEG, PNG, WebP and GIF for a large card; [X cards markup](https://developer.x.com/en/docs/x-for-websites/cards/overview/markup)); not re-fetched on 2026-11-25, the page now redirects to a generic docs home | documented earlier, same source, not re-checked                                                                                                                                                                                        |
| Discord                   | documented: [link previews, Images](https://docs.discord.com/developers/link-previews/overview) lists `.png`, `.gif`, `.jpg`, `.jpeg`, `.webp`, `.avif`                                                                                         | documented: the same page                                                                                                                                                                                                              |
| Telegram                  | unverified by the platform; widely used                                                                                                                                                                                                         | reported not shown: an unresolved [Telegram Desktop issue](https://github.com/telegramdesktop/tdesktop/issues/16312) (2021 to 2022, several users on desktop, macOS and iOS) says a WebP `og:image` gives no preview. Not tested by us |
| WhatsApp, Slack, iMessage | unverified by the platform; widely used                                                                                                                                                                                                         | unverified: no platform statement found                                                                                                                                                                                                |

So JPEG is the safe choice for photo cards, and WebP is for a site whose audience we know only uses platforms that read it. The default stays PNG.
Probe a deployment before relying on WebP: `curl -I` the card URL (`content-type: image/webp`), then paste a page into each platform's
own debugger (Facebook Sharing Debugger, LinkedIn Post Inspector) and into a real Telegram chat.

Turn on `crawlerEvents: { sample: 0.1 }` to learn which crawlers actually hit your cards and how often a
first fetch is a cold render.
